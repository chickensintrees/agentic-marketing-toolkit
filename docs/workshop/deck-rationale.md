# Deck rationale

Guest lecture by Bill Moore: a marketing class at West Virginia University,
Monday 9 November 2026, 60 minutes.

Current as of revision 4. Bill set the title and framing himself and edits
the deck directly.

## The framing (Bill's)

> "It's more about how we use harnesses to control agents to build tools and
> how we collaborate on building tools, products, even businesses in
> GitHub."

**Title:** How products get built

**Subtitle:** Harnesses for AI agents, and collaboration on GitHub

The two topics:

1. **Harnesses.** A spec, rules, skills, tools and checks direct AI agents so
   they build the tools we want.
2. **Collaboration on GitHub.** People and their agents work on one
   repository through branches, pull requests and comments. Once an agent
   is connected to GitHub, it carries out the git steps and a person
   approves each public action.

The Agentic Marketing Toolkit is a worked example of both. The same pattern
applies to building products and businesses.

**On-screen register:** plain academic wording, no slogans or taglines
(Bill: "We are making a slide deck to be presented in a university").
The close is a two-point summary.

## Bill's brief, condensed

- Show his work. Get students building their own tools with Claude Code,
  Codex, Cursor, Lovable or Replit.
- Teach GitHub basics, how to connect GitHub to a coding agent, and how to
  collaborate through commits, pushes, merges and pull requests.
- Use Slido moments, including a word cloud that feeds the discussion.
- Use a Porter's Five Forces app as the example that students can extend
  through pull requests.
- Cover harness engineering, starting from the word's origin.
- The class builds a product together: a growing suite of tools, with Bill's
  ongoing support. Contributing is voluntary unless the instructor assigns
  it.
- Connecting the agent to GitHub is the key, because the agent then manages
  the git.

## Editorial rule (Bill's)

On screen, show only titles plus the minimum facts, labels, prompts,
commands or URLs. There are no taglines, quips or editorializing.
Commentary goes in the speaker notes, which stay plain and factual.

## Audience

- **Marketing students.** They are studying Porter, and they know briefs and
  positioning. Few have used a terminal, GitHub or a pull request.
- **The professor.** They want the course content reinforced, and they
  decide whether contributing is assigned.

## Outcomes

| | |
|---|---|
| **Know** | How a harness (spec, rules, skills, tools, checks) keeps agents building what you want. How people and agents collaborate in one GitHub repo. That connecting your agent to GitHub lets it do the git while you approve. |
| **Be able to do** | Paste the starter prompt into a coding agent, connect it to GitHub with a browser sign-in, and open a pull request against the Agentic Marketing Toolkit. With no paid tool, make a one-file change in GitHub's web editor instead. |

## The arc (60 minutes, 18 slides)

| Min | Slides | Content |
|---|---|---|
| 0–5 | 1–2 | Introduction: cover, about me. |
| 5–11 | 3–4 | Part 1: what a harness does; the five components (spec, rules, skills, tools, checks). |
| 11–22 | 5–7 | Part 2: GitHub basics, how a contribution moves, connecting an agent to GitHub. |
| 22–41 | 8–13 | Examples: work at BCG; the toolkit and the live site; the live demonstration (the prompt, how this was built while the agent works, from change to merge). |
| 41–48 | 14–16 | The poll (one word cloud), how to contribute, tools and plans. |
| 48–60 | 17–18 | Summary, then questions (Slido Q&A). |

**Live-demo risk:** the GitHub sign-in is done in advance. The industry is
Bill's choice (or one suggestion from the room), and a fallback branch and PR
is prepared for Bill's planned industry. The "How this was built" slide fills
the agent's working time. The hard stops are in `run-of-show.md`.

**Audience participation (Bill's decision):** one Slido poll, asked after
everything has been explained, plus Slido Q&A at the end.

## Left out

- The original 28-slide deck and its "rent versus build" title.
- Git theory and code walkthroughs.
- Statistics or claims that were not verified. Plan prices and tool facts
  come from official docs, checked 8 November 2026.
