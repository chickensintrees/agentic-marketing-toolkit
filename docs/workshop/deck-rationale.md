# Deck rationale

Guest lecture by Bill Moore: a marketing class at West Virginia University,
Monday 9 November 2026, 60 minutes.

Current as of revision 4. Bill set the title and framing himself and edits
the deck directly.

## The framing (Bill's)

> "It's more about how we use harnesses to control agents to build tools and
> how we collaborate on building tools, products, even businesses in
> GitHub."

**Title:** How products get built

**Subtitle:** Harnesses steer the agents. GitHub is where we build together:
tools, products, even businesses.

The two ideas:

1. **Harnesses steer the agents.** Specs, rules, skills and checks are how
   we control agents so they build the tools we want.
2. **GitHub is where we build together.** People and their agents
   collaborate on one repo through branches, pull requests and comments.
   The key is connecting your agent to GitHub, because then the agent does
   the git.

The Agentic Marketing Toolkit is the worked example of both ideas. The same
pattern builds products and businesses.

**Line to repeat:** "My agent does the git. I make the calls."

## Bill's brief, condensed

- Show his work. Get students building their own tools with Claude Code,
  Codex, Cursor, Lovable or Replit.
- Teach GitHub basics, how to connect GitHub to a coding agent, and how to
  collaborate through commits, pushes, merges and pull requests.
- Use Slido moments, including a word cloud that feeds the discussion.
- Use a Porter's Five Forces app as the example that students can extend
  through pull requests.
- Cover harness engineering, starting from the word's origin.
- The class builds a product together: a growing suite of tools, with Bill's
  ongoing support. Contributing is voluntary unless the instructor assigns
  it.
- Connecting the agent to GitHub is the key, because the agent then manages
  the git.

## Editorial rule (Bill's)

On screen, show only titles plus the minimum facts, labels, prompts,
commands or URLs. There are no taglines, quips or editorializing.
Commentary goes in the speaker notes, which stay plain and factual.

## Audience

- **Marketing students.** They are studying Porter, and they know briefs and
  positioning. Few have used a terminal, GitHub or a pull request.
- **The professor.** They want the course content reinforced, and they
  decide whether contributing is assigned.

## Outcomes

| | |
|---|---|
| **Know** | How a harness (spec, AGENTS.md, skills, checks) keeps agents building what you want. How people and agents collaborate in one GitHub repo. That connecting your agent to GitHub lets it do the git while you approve. |
| **Be able to do** | Paste the starter prompt into a coding agent, connect it to GitHub with a browser sign-in, and open a pull request against the Agentic Marketing Toolkit. With no paid tool, make a one-file change in GitHub's web editor instead. |

## The arc (60 minutes, 17 slides)

| Min | Slides | Content |
|---|---|---|
| 0–6 | 1–3 | Cover with the two ideas. The live site. Poll 1 (word cloud). |
| 6–14 | 4–5 | About me. How this was built: spec, split, coordinate, integrate, with the build graph. |
| 14–20 | 6–7 | Idea 1: the harness (etymology), and the harness in this repo. |
| 20–38 | 8–12 | Idea 2: connect your agent to GitHub. Poll 2 (industry). The prompt and the live Claude Code change. Poll 3 (Porter rating) while it works. From plan to merge. |
| 38–50 | 13–15 | The toolkit as the worked example. Contribute. What you'll need. |
| 50–60 | 16–17 | Q&A, then the close. |

**Live-demo risk:** the GitHub sign-in is done in advance. Each poll option
has a prepared fallback branch and PR. The Porter exercise fills the
agent's wait. Hard stops are in `run-of-show.md`.
